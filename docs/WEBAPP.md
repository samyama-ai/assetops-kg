# Audit web app — audit-insights

The reproduction audit is presented as a Lovable single-page app. Its repo is the
single home for the app code, the Lovable prompts, the Playwright specs, and the issue
backlog (same convention as db-internals).

- **GitHub:** https://github.com/VaidhyaMegha/audit-insights (Lovable syncs `main`)
- **Gitea mirror (private):** git@git.samyama.ai:Samyama.ai/audit-insights.git
- **Local clone:** `graph_ws/audit-insights` — `npm run e2e` runs the contract.

## The data bridge (this repo's only role in the app)

The app hardcodes no numbers. It reads `public/data/audit.json`, generated by:

    python -m evaluation.export_audit_json

That script writes **directly into** `../audit-insights/public/data/audit.json` when the
sibling clone is present. Regenerate after any change to `results/`, then commit in the
app repo. Every value there is read from `results/*.json` — never transcribed.
