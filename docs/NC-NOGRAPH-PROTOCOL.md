# Negative control: does the graph contribute anything to GAK?

**Frozen 2026-07-13, BEFORE writing the control code or looking at any result.**

## Why

GAK (Architecture D, paper3 §5.7) reports 81.8% (claude-sonnet-4-5), 73.9% (gpt-4.1),
52.3% (gpt-4o) on 88 HF failure-mode scenarios. Code review found two defects that
together suggest the graph is a **pass-through**:

1. **`run_gak.py:250-255`** — the answer step never receives the question.
   `subgraph_answer(entity)` dumps *all* failure modes for the entity; all scenarios
   for that entity are graded against that one string. 88 scenarios → 10 answers.

2. **`run_gak.py:45-52` (`SCHEMA_HINT`)** — GAK instructs the LLM to create
   `(:Equipment)-[:HAS_FAILURE_MODE]->(:FailureMode)`. **No ETL loader creates
   `HAS_FAILURE_MODE`** (the real edge is `:EXPERIENCED`). GAK writes that edge
   and then queries for that edge. So `baseline_answerable=False` is guaranteed by
   a wrong-edge-type query, and `enriched_answerable=True` is guaranteed by
   construction. The reported "answerability lift 0 → 100%" cannot fail.

If the graph is a pass-through, then GAK ≈ "ask an LLM for the failure modes of
equipment X, store the answer, read it back, grade it." The graph adds nothing.

## Hypothesis under test

**H0 (null, what we currently claim):** the typed graph contributes to GAK's pass
rate. Removing it degrades performance.

**H1 (what the code review predicts):** the graph contributes nothing. Removing it
changes nothing, and *fixing the question-blindness* improves things — meaning the
current pipeline is net-negative versus just asking the LLM.

## Arms (same 88 scenarios, same judge, same rubrics)

Judge held **fixed and identical to `run_gak.py:92`**: `gpt-4o`, `temperature=0.0`,
`response_format=json_object`, same system + user prompt, graded against each
scenario's `characteristic_form`. No graph is touched in any control arm.

| arm | answer generated by | sees the question? | touches graph? |
|-----|---------------------|--------------------|----------------|
| **GAK** (published, for reference) | LLM writes Cypher → graph → template dump | **no** | yes (writes then reads its own nodes) |
| **C1: no-graph, question-aware** | LLM answers the question directly | **yes** | no |
| **C2: no-graph, question-blind** | LLM lists all failure modes + sensors for the entity; that one string grades all of the entity's scenarios | **no** | no |

**C2 is the decisive arm.** It reproduces GAK's question-blindness *exactly* but
deletes the graph round-trip. It isolates the graph as the only changed variable.

Models: `gpt-4o`, `gpt-4.1`. (No Anthropic key available in this repo, so
claude-sonnet-4-5 cannot be re-run; the two GPT models are where GAK looks worst
and are sufficient to decide the question.)

## Pre-registered decision rules

Let Δ = C2 − GAK (same model), in percentage points.

- **|Δ| ≤ 5 pp → the graph is a pass-through.** GAK's number is the LLM's parametric
  knowledge round-tripped through a database. The graph contributes nothing, and
  paper3's Architecture D claim does not survive.
- **Δ ≤ −5 pp (C2 clearly worse) → the graph genuinely contributes.** H1 is refuted;
  the published GAK claim is defensible and I was wrong.
- **Δ ≥ +5 pp → the graph is actively harmful** (the write/read round-trip loses
  information the LLM already had).

Separately, let Γ = C1 − GAK.

- **Γ > 0 → the question-blind design is destroying performance**, independent of the
  graph. The published pipeline is worse than simply asking the LLM.

## What would make me wrong

- If C2 lands well *below* GAK, the graph is doing real work (e.g. the enrichment
  prompt's schema constraints force better-structured knowledge than free text).
  I will report that and retract the code-review conclusion.
- If the judge turns out to be the confound (e.g. it rewards the template's bullet
  format regardless of content), C1/C2/GAK will cluster for format reasons, not
  knowledge reasons. **Mitigation:** C2 is emitted in the same bulleted
  `- <mode> (severity: ...); detected by: ...` shape as the GAK template, so format
  is held constant between C2 and GAK.
